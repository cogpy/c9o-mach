# Archived Build Artifacts

This manifest inventories files that were removed from version control in
commit `6e5fb19` ("perf: optimize repository size and CI pipeline") to keep
the repository lean. Nothing hand-written was removed; every entry is a
compiled binary, a build log, a generated file, or patch debris.

## How to recover the exact original files

Every file below still exists in git history at the commit immediately
before removal (`ff3ed8a`, i.e. `6e5fb19^`). To restore one:

```
git checkout 6e5fb19^ -- <path>
```

To restore all of them into this `archived/` directory (which is
git-ignored, so it will not re-enter the tracked tree):

```
mkdir -p archived
git archive 6e5fb19^ -- $(git show --diff-filter=D --name-only --format="" 6e5fb19) \
    | tar -x -C archived/
```

The `archived/` directory is listed in `.gitignore` (only this manifest is
tracked), so restoring the contents preserves the clone-size optimization
while leaving the artifacts available locally for inspection.

## Why these were removed

Compiled binaries, logs, and `configure`/`make` output do not belong in
version control: they bloat every clone, never merge cleanly, and are
regenerated from tracked sources on demand. `.gitignore` was extended in the
same commit to keep build trees, logs, patch debris, and compiled binaries
out of the tracked tree going forward.
